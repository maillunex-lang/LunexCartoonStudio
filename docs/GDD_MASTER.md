# Lunex Cartoon Studio - Master GDD v0.1 (DRAFT)

Дата: 2026-11-22. Статус: обсуждение, не утверждён целиком.
Назначение: продуктовый и технический канон будущей студии автоматического производства 3D-мультфильмов.

## 1. Видение
Пользователь вводит идею или сценарий, выбирает сериал, персонажей, стиль, длительность и параметры выпуска. Система планирует сцены, выбирает ассеты и анимации, собирает проект Blender, рендерит быстрый предпросмотр, позволяет внести правки, затем выдаёт проверенный MP4 и воспроизводимый проект. Codex отвечает за генерацию и обслуживание сценарно-постановочного кода; детерминированный worker выполняет рендер. Результат требует художественной приёмки человеком.

## 2. Утверждённый канон
- STUDIO-001 D: автоматизированная фабрика мультфильмов по сценарию, управляемая Codex.
- ASSET-001 C: Meshy AI для оригинальных моделей + готовые лицензированные анимации + Blender для адаптации и постановки.
Никакие другие пункты этого документа не считать утверждёнными без решения владельца.

## 3. Пользовательский цикл (проект)
Создать проект/сериал -> выбрать персонажей/локации -> ввести идею -> сгенерировать сценарий -> согласовать раскадровку -> проверить ресурсы -> собрать сцену -> получить low-res preview -> отредактировать отдельные сцены -> запустить финальный рендер -> проверить QC -> экспортировать MP4, проект и manifest.

## 4. Модули продукта (проект)
1. Projects & Series: сериалы, сезоны, эпизоды, стиль, шаблоны.
2. Character Studio: 3D-модели, скелеты, материалы, лица, варианты, паспорта.
3. Animation Library: клипы, превью, теги, риги, совместимость, ретаргетинг, переходы, слои.
4. World & Props: локации, декорации, объекты, свет, камеры.
5. Story & Director: сценарий, shot list, таймлайн, действие, камера, блокинг, эмоции.
6. Render Farm: очереди, приоритеты, worker, предпросмотр, retry, отмена, артефакты.
7. Review & QC: просмотр по сценам, замечания, технические проверки, версии.
8. Asset Provenance: лицензии, атрибуция, хэши, условия коммерческого использования.
9. Integrations: Meshy API при наличии доступа, импорт FBX/GLB/BLEND, FFmpeg, Codex.
10. Administration: роли, квоты, логи, стоимость, настройки.

## 5. Предварительная архитектура
React UI -> FastAPI backend -> PostgreSQL (метаданные) + object/file storage (большие ресурсы) -> job queue -> isolated Blender Python worker -> FFmpeg -> artifacts.
Codex создаёт структурированную постановку и кодовые адаптеры, а не исполняет непроверенные произвольные скрипты в публичном API. JSON Schema для episode и asset manifests; frame-based timeline; pinned versions, seeds and checksums for reproducibility.

## 6. Модель данных
Series, Season, Episode, ScriptRevision, Shot, TimelineAction, Character, RigProfile, AnimationClip, Environment, Prop, AssetVersion, LicenseRecord, RenderJob, RenderArtifact, ReviewComment, QCReport, IntegrationCredentialRef.
Состояния эпизода: draft -> storyboard_review -> assets_ready -> preview_rendering -> preview_review -> approved_for_final -> final_rendering -> qc_review -> published/archived. Ошибки и возврат на доработку отдельно.

## 7. Пилот и критерии качества (проект)
Тест: 15 секунд, один герой, одна комната, пять движений.
Первый выпуск: Мишка обучает счёту 1-10, 3 минуты, 16:9, 1920x1080, без звука.
Приёмка: стабильные движения и камера, отсутствие визуальных артефактов, точная длительность, воспроизводимость, чистая лицензия, доступность файлов проекта и MP4.
Тестовые процедурные модели не подменяют итоговые Meshy-модели.

## 8. Безопасность, ограничения и риски
Не сохранять секреты API в Git; хранить лицензии и происхождение ресурсов; изолировать Blender workers; не исполнять код из непроверенного сценария; валидировать пути и загрузки; вводить квоты рендера. CPU VPS может быть слишком медленным для 1080p; перед выбором инфраструктуры измерить 15-секундный benchmark. Ретаргетинг требует совместимости скелетов, мимика и взаимодействие с реквизитом требуют дополнительных rig/IK инструментов. Автоматический QC не заменяет ручной просмотр.

## 10. GDD-01: вопросы владельцу (пока не утверждены)
**AUTO-001**: A - сценарий -> preview -> ручное утверждение -> final; B - почти полностью автоматический выпуск; C - покадровая ручная сборка с AI-помощником. Рекомендация A.
**EDIT-001**: A - редактирование только текста; B - текст + визуальный таймлайн сцен; C - полноценный 3D-редактор в браузере. Рекомендация B.
**OUTPUT-001**: A - только 16:9; B - 16:9 и 9:16; C - произвольные форматы. Рекомендация B.
**SCOPE-001**: A - только детские обучающие; B - любые мультфильмы с единой архитектурой; C - только один сериал. Рекомендация B.
**APPROVAL-001**: A - обязательное утверждение preview перед финалом; B - опциональное; C - без утверждения. Рекомендация A.

## 11. Порядок утверждения
Согласовываем GDD-01...10 по очереди. Каждое принятое решение переносим в docs/GDD_DECISIONS.md. Только после утверждения архитектурно значимых блоков пересматриваем ROADMAP и возобновляем разработку. Уже существующие прототипы и схемы сохраняются как экспериментальные, а не как окончательный канон.
