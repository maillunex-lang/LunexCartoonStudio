# Новый GDD-план v2

Статус: новый цикл, **1/10 GDD утверждён по функциям (DEVICE-001 уточнён до A); 0/10 принято владельцем**. Предыдущий GDD и его решения сброшены по явному решению владельца; не считать их действующим каноном.

## Обязательный цикл каждого этапа
1. **DESIGN**: варианты A/B/C, рекомендации, критерии результата.
2. **APPROVAL**: владелец утверждает коды решений.
3. **RESEARCH**: поиск GitHub-проектов, готовых библиотек и решений; минимум 2-3 кандидата при наличии; документировать лицензии, активность, API, сложность и риски.
4. **TECH APPROVAL (обязательно)**: подготовить конкретный перечень «внедряем / адаптируем / пишем сами» с вариантами A/B/C, лицензиями, рисками и рекомендацией. Получить явное утверждение владельца **до любой интеграции**.
5. **IMPLEMENT**: интегрировать выбранное решение в рабочий проект, фиксировать коммиты и зависимости.
6. **TEST**: сборка, автоматические тесты, браузерный smoke, проверка экспорта и лицензий, воспроизводимая инструкция.
7. **ACCEPTANCE**: демонстрация и приёмка владельцем. Только после неё этап DONE и переход дальше.
